## 二、数据搬家

### 为什么不用「云同步」

真正的云同步需要服务器、账号、账号体系与隐私政策，和这个 App 从 v1.0 起的承诺（不联网、不上传、不注册）冲突；而且一台闹钟 App 为了备份去收集用户作息，代价远大于收益。

所以这版做的是**文件级搬家**：数据打包成一个 JSON，用户自己决定放哪儿。系统的 `ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT` 选择器里本来就列着「下载」和用户登录过的网盘，所以「存本地」和「存云端」对用户是同一个动作——**不需要 App 接任何云服务**。

### 打包内容

| 块 | 键 | 内容 |
|---|---|---|
| 闹钟 | `alarms` | 时间、重复、贪睡分钟、每轮题数 |
| 打卡记录 | `records` | 每天是否完成、答题对错数、照片路径 |
| 设置与画像 | `settings` | 主题、语速、地区、画像、战力、总分 |
| 流水 | `journal` | 每一条答题 / 播报 / 打卡事件（上限 3000） |

信封格式（`schema: 1`，向后兼容用）：

```json
{
  "app": "morning",
  "schema": 1,
  "version": "1.15.0",
  "exportedAt": "2026-11-23T21:40:00.000",
  "prefs": { "alarms": [...], "records": [...], "settings": {...}, "journal": [...] }
}
```

### 合并规则（`Portable.mergeInto`，纯函数）

- **闹钟**：按「几点几分 + 哪几天」判同一只，重复的跳过；缺的补进来，id 冲突时换新号（避免两只闹钟共用一个 PendingIntent）
- **打卡记录**：按日期；同一天取信息更全的一份（完成状态取并集、题数取大）；照片路径只认本机真实存在的文件——跨手机的路径一定是空的
- **流水**：按「时间 + 类型 + 标题」去重，合并后倒序，守 3000 条上限
- **设置**：本机已有的值优先；`flowPending` / `flowPendingStep` / `lastTrigger` 这类「进行中状态」不搬（否则新手机一启动就被拽进晨间流程）
- **画像 / 战力 / 分数**：整份取「答得更多」的那一边，**不做加法**。理由：它们是连着答出来的三本账，两台手机各答一半再相加会出现「答过 800 道但战力只有 50」的自相矛盾状态

### 安全措施

1. 解析不过（不是 JSON / 不是本 App / 格式版本更新 / 一个块都认不出）→ 抛 `BackupError`，**一个字节都不写盘**
2. 覆盖前把当前数据写到 `files/backups/pre_import.json`，页面提供「撤销导入」
3. 导入后 `Store.alarms / records / settings` 先清空再 `load()`——`Store.load()` 对空字符串是「跳过不覆盖」，不清空的话覆盖导入会读到旧列表再写回去
4. 导入后 `Store.saveAlarms()` 重新登记系统闹钟（只改 prefs 不重排，系统里还是旧闹钟）

### 原生实现（`MainActivity.kt`）

| 方法 | 作用 |
|---|---|
| `exportData(json, name)` | `ACTION_CREATE_DOCUMENT`，`openOutputStream(uri, "wt")` 截断写 |
| `importData()` | `ACTION_OPEN_DOCUMENT`，`BufferedReader(UTF-8).readText()`（不自己切字节缓冲，避免中文在边界被切断） |
| `shareData(json, name)` | 写 `cache/share/` + FileProvider + `ACTION_SEND` |
| `saveLocal / readLocal` | 私有目录 `files/backups/` 读写（自动备份） |

**没有新增任何权限**：SAF 不需要存储权限。

## 三、答题总分

### 口径

| 情况 | 分值 | 理由 |
|---|---|---|
| 完全答对 | **+1** | 用户原话 |
| 答错 / 多选漏选 | **−1** | 没选全就是没答对，不给「半分」这种解释不清的中间态 |
| 主动跳过 | **0** | 跳过是「这块先不问」，罚分只会让人瞎猜，把画像喂脏 |
| 偏好题 | **0** | 没有标准答案，本来就没有对错 |

分数可以是负数，不夹到 0。

### 展示位置

1. **「我的」顶部卡**：连续天数旁边并列「总分」
2. **「我的」→ 总分行**：点开是记分规则说明（含对/错/跳过/正确率）
3. **画像卡**：总分大字 + 答对/答错/正确率/跳过，紧跟在「画像」标题下
4. **答题页右上角**：常驻「总分 N」
5. **本轮小结**：「本轮 +N」+ 总分 + 一行规则

### 实现

- `ScoreBook`（`lib/score.dart`）：`right / wrong / skipped / pref` 四计数，`total = right − wrong`，存在 `settings['score']`
- `QuizTally` 新增 `points` 字段：本轮得分不能由「答了几道、对了几道」反推（偏好题与跳过都是 0 分），必须单独记
- 判分入口在 `QuizPane._finish`（`lib/quiz_pane.dart`），跳过在 `_skip`

### 修掉的一个布局问题

给「我的」顶部卡加「总分」后，测试报 `RenderFlex overflowed by 15 pixels`：机型名那一列是固有宽度，多一个数字列就把右边挤出屏幕。改为中间列 `Expanded` + 设备名 `ellipsis`，真机上不会报错、只是「看不见」，属于只有测试才抓得到的坑。

## 六、遗留与建议

1. **云端同步**仍是「文件搬家」而非「多端实时同步」。真要同步，需要账号 + 服务端 + 冲突解决，属于另一个版本的事
2. **照片不进备份**：打卡照片是 MB 级图片，塞进 JSON 会让文件无法传输。换机后记录在、照片空
3. **targetSdk 34 跑在 Android 16 上**：建议下一版提到 35/36 再复测响铃链路
4. **release 仍是 debug 签名**：下载即可安装，但换 keystore 会导致老用户无法覆盖升级——发正式版前要一次性定下来
