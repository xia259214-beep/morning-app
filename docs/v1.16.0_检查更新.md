# v1.16.0 · 应用内检查更新

> 起因：用户在手机上打开 App，期待「有新版本」的提示，但什么都没发生。
> 查下来不是提示被关掉了，而是**这个功能从来没写过**——App 里没有任何一行代码问过
> 「线上最新是哪个版本」。v1.15.0 之前的更新方式只有一种：自己去 GitHub 下载 APK 覆盖安装。

## 一、这次加了什么

| 入口 | 行为 |
|---|---|
| 开屏（延迟 3 秒） | 静默查一次；**只有真有新版**才弹窗，其余情况一声不响 |
| 我的 → 版本（点整行） | 手动检查，必有回话：有新版的弹窗 / 「已是最新 v1.16.0」/ 「查不到更新」+ 发布页快捷入口 |
| 弹窗里的「去下载」 | 用系统浏览器打开 APK 直链，下完点安装即可覆盖 |
| 弹窗里的「以后再说」 | 该版本 **3 天内**不再弹（手动检查不受此限） |

弹窗同时写清了安装动作：「点去下载 → 下完点安装 → 系统问是否允许安装时选允许」，
以及「不用卸载旧版，数据不会丢」——这是用户最怕的一件事，得写在按钮旁边而不是文档里。

## 二、机制与取舍

- **问的是 GitHub Release API**：`GET /repos/xia259214-beep/morning-app/releases/latest`，
  取 `tag_name` 比版本、从 `assets` 里挑第一个 `.apk` 的 `browser_download_url`。
  没挂 APK 时退回 release 页面，不会给出空链接。
- **零第三方依赖**：用 `dart:io` 的 HttpClient。为了一个「有没有新版」的判断题引一整个
  更新 SDK 不划算，也违背这个项目一直的零依赖约定。
- **节流 12 小时**：开屏才查，且半天最多一次。手机每早开一次，实际就是「一天一问」。
- **失败静默**：断网、GitHub 访问不稳、接口限流一律吞掉，不弹错误、不打断。早上七点
  被人叫醒的时候没人想看「网络异常」。失败后 1 小时内不再重试，避免每次开屏都卡超时。
- **不打扰晨间流程**：首次引导没走完、或正处在晨间流程页（被闹钟叫醒）时，本次不检查。
- **版本比较按数字逐段比**：`1.9.0 < 1.10.0`（字符串比较会判反，这是最容易踩的坑）；
  `v` 前缀、`+构建号`、`-预发布后缀` 都不参与比较。
- **不再自动装**：Android 不允许应用静默安装自己的更新（需要用户点系统安装器）。
  「应用内检查 + 浏览器下载 + 系统安装器」是侧载分发的标准路径，也是唯一不需要
  危险权限的路径。

## 三、顺手修的一个错

`lib/core.dart` 的 `kAppVersion` 还停在 **1.12.1**，而包已经是 1.15.0 —— 崩溃日志里
写的版本号是错的，用户报问题时对不上号。已改为 1.16.0，并新增
`test/version_sync_test.dart`：直接读 `pubspec.yaml` 跟常量比，改版本忘了同步就红。

## 五、未验证项（设备没连，如实记录）

平板当时未连接（`adb devices` 为空），工程里的模拟器又缺硬件加速起不来，所以：

1. **弹窗没有在真机上点过**。逻辑层有单测，但「弹窗长什么样、按钮点下去浏览器是否拉起」
   未实测。
2. **真机（国内网络）能否访问 `api.github.com`** 未实测。本机 curl 可通、返回结构符合预期；
   若用户网络访问不了 GitHub，表现为「查不到更新」，不影响 App 其他功能。
3. 从旧版本覆盖安装新版本、数据是否保留——v1.15.0 之前每次发版都是覆盖安装，路径成熟，
   但这次同样没在设备上复核。

建议下次设备接上后补：启动 → 等弹窗 → 点「去下载」→ 浏览器下载 → 系统安装器覆盖安装
→ 打开确认闹钟与记录还在。

## 六、更新方式（用户视角，发版时可直接贴到 release 说明）

1. 打开「晨序MORNING」→ 我的 → 版本，点一下；或直接开 App 等几秒
2. 看到「有新版本」→ 点「去下载」
3. 浏览器下完 APK，点它 → 系统问「是否允许安装未知应用」，选允许
4. 装完直接打开，闹钟和记录都还在

> 旧版本（v1.15.0 及更早）里没有这段代码，**必须手动更新一次**，之后才会有提示。
