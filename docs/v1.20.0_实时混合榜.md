# v1.20.0 · 实时排名 + 真人/内置混合榜

## 用户要的是什么

原话：「答题排名能不能搞成实时排名……看到排名多少分，每个人答题多少多少分，超过一个人会更有激情。」

拆成两条：① 名次当场跳，不泡在网络请求里；② 榜上要有人可超，不能是空的。

## 为什么这么做

### 自己的名次：本地实时

`lib/leaderboard.dart` 的 `Leaderboard.snapshot()` 是纯函数——给自己分数、真人列表，当场算出名次、超过人数、正前面那个人差几分。QuizPane 每判完一道题回调 `onAnswered`，答题页 `setState` 立刻重排。**不需要等网络**，飞行模式下也跳。

### 真人榜：开了云后端，但不做账号

- 后端：WorkBuddy Cloud Service，应用 `wbapp_orbTScPbe7o7jxfIQylpc4`，域名 `morning-rank.app.workbuddy.host`（国内可直连）。
- 数据表 `morning_scores`：匿名设备 ID 主键 + 昵称 + 总分 + 对错数 + 答题数 + 城市 + 版本 + 更新时间。
- RLS：所有人可读；匿名可 insert/update（上传自己的分数）。有 CHECK 约束挡住离谱分数（总分 ±10 万、次数 0~100 万、昵称 1~24 字）。
- 身份是首次启动随机生成的 32 位十六进制 ID，存本机设置，跟着 JSON 备份搬家——换设备导入备份后还是同一个「真人」，不会凭空多一人。**不收手机号、邮箱，不做注册登录**，之前「不联网也能用」的立场继续守着。

### Flutter 怎么连的

官方 SDK 只有 JS 和小程序版，没有 Dart 版；本项目零第三方依赖，所以用现成的 `dart:io HttpClient` 直连数据面。认证头从 SDK 源码里查到是 `x-wb-webapp-access-key`（不是 `apikey`、不是 `Authorization`），值就是公开的 `publishableKey`。两个值作为常量写进 `leaderboard.dart`——这是云服务返回的公开配置，本身不带权限。

- 拉榜：`GET /.cloud/database/rest/morning_scores?select=...&order=total.desc&limit=50`
- 上报：`POST` 同路径，`Prefer: resolution=merge-duplicates` 按设备 ID upsert
- 节流：3 小时拉一次；失败静默、用上次缓存，不弹错误打断用户

### 内置对手：1:1 混排，明确标注

真人有几个就配几个内置对手（一个真人都没有时给 8 个，冷启动榜不空）。内置分数 = 我的分数 + 固定偏移，前四在后四在前：

| 对手 | 阿泽 | 小满 | 林间 | 青禾 | 阿禾 | 北屿 | 山雀 | 晚舟 |
|---|---|---|---|---|---|---|---|---|
| 偏移 | +30 | +20 | +12 | +7 | **+3** | −4 | −9 | −15 |

所以前面永远有个「再得 3 分就超过阿禾」的够得着目标，后面永远有人刚被你超过。**内置对手在 UI 上带「内置」标签**，不冒充真人。它们只在本机算，不进数据库。

## 隐私开关

榜单页有「参与真人榜」开关：

- 开（默认，因为你明确要真人榜）：上报分数，3 小时刷新一次
- 关：不上报任何数据，只用内置对手，和 v1.19.0 之前完全一样

真人分数是本人自愿匿名上报的，理论上可以伪造——本地应用防不住作弊，榜单按「激励工具」定位，不做竞技级防伪。

- `flutter test`：256 项全过，其中 `test/leaderboard_test.dart` 8 项覆盖名次计算、1:1 配比、锚定目标、真人清洗、缓存容错

## 真机发现并修掉的 bug

**中文昵称导致上报必失败**。平板点「上报分数」后云端一直空，logcat 抓到：
```
[RANK] upload ERR=Invalid argument (string): Contains invalid characters.:
  "[{\"device_id\":\"...\",\"nick\":\"晨友\",...}]"
```
根因：`HttpClientRequest.write()` 默认按 Latin-1 编码，写不了中文。默认昵称恰好就是「晨友」，所以**每个新用户的第一次上报都必失败**，且被 catch 静默吞掉，界面只显示「上报失败」。改成 `req.add(utf8.encode(body))` 后修复。这个 bug 只有真机能发现——单测里的真人数据是纯逻辑对象，不走网络编码。

## 真机验证（平板 24018RPACC）

- 进榜单页：`第 6 名 · 超过 3 人 · 共 9 人`、`再得 3 分超过「阿禾」`，内置对手分数 30/20/12/7/3/0/-4/-9/-15 全部正确
- 「我的」页那行：`第 6 名 · 超过 3 人 · 初醒`，实时名次生效
- 内置对手带「内置」标签；「0 位真人 · 8 位内置对手」说明文字完整
- 参与开关默认开，可关闭转为纯离线
- 真人上报：修 UTF-8 后 logcat 显示 `upload done code=201`，云端查到该设备记录（nick=晨友、总分、答题数、版本都对）
- 真人上榜 + 1:1：插入一条测试真人（5 分）后点刷新，`pull ok 2 rows`，榜上出现无「内置」标签的真人，`1 位真人 · 1 位内置对手`，追超提示变成「再得 5 分超过…」，名次从第 6 名重算为第 3 名
- 测试数据已从云端清除，交付时榜单是空的（没有真人时显示 8 位内置对手）

## 已知取舍

- **真人少时名次会"变好"**：严格按 1:1，真人从 0 增到 1 时内置对手从 8 减到 1，总人数 9→3，我的名次 6→3。心理上"别人加入我却前进"有点怪。若想改成"内置对手固定 8 个、真人在上面叠加"，改 `Leaderboard.snapshot()` 里的 `builtInCount` 一行即可。
- 真人分数匿名上报，理论上可伪造，定位是激励工具不是竞技榜。
- 手机端未插 adb，未验证；手机升级到 1.20.0 后规则与平板一致。
