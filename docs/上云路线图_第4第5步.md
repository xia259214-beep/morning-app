# 上云路线图 · 第 4/5 步实施方案

> 生成：2026-11-22 凌晨（第 4/5 步需要账号注册，AI 无法代办；本文档把准备工作做到"给配置就能开工"的程度）

## 第 4 步：账号 + 云同步（免费额度内）

### 目标
换机不丢数据：晨间记录、打卡照片元数据、答题画像、闹钟配置自动同步。

### 需要用户做的事（约 10 分钟）
1. 选平台（二选一）：
   - **Firebase**（Google）：https://console.firebase.google.com 创建项目 → 添加 Android 应用（包名 `cn.morning.morning`）→ 下载 `google-services.json` 放到 `android/app/`
   - **Supabase**（开源）：https://supabase.com 创建项目 → 拿到 URL + anon key
2. 把配置文件/密钥交给 AI

### 代码侧已预留的接入点
- 数据全部经 `core.dart` 的 `Store`/`Journal` 读写 → 只需在这两处加"写后同步钩子"
- 账号建议**游客账号**（首次启动生成本地 UUID，静默注册），不强迫注册
- 冲突策略：以设备时间戳新的为准（个人使用无多端并发场景）

### 引入 SDK 的影响
- 打破"零第三方依赖"（v1.11.0 仍是零依赖）
- Firebase 需要改 `android/build.gradle`；Supabase 走 REST 可不加原生 SDK（推荐，冲击更小）

## 第 5 步：新闻引擎后端化（可能有费用）

### 目标
新闻抓取从"手机直连公开网站"搬到服务端，首页秒开、手机省电、源站改版由服务端修。

### 前置依赖
先做第 4 步（有账号体系后，服务端才知道给谁推数据）。

### 需要用户做的事
- 免费路线：GitHub Actions 定时抓取（每天 5:00/8:30/19:00 三档）→ 结果 commit 到仓库或存 Release → App 拉取。**零费用**，但 GitHub Actions 国内访问可能不稳
- 付费路线：轻量云函数（腾讯云 SCF / Cloudflare Workers）+ CDN，按量计费，个人用量每月几元以内

### 决策点（中午确认）
1. 仓库是否改公开（第 3 步 Pages 需要，且 Release 下载私有库需要登录）
2. 第 4 步选 Firebase 还是 Supabase
3. 新闻后端化走免费（Actions）还是轻付费路线
